Modo de replicación

Se aplica a todos los primarios (synchronous_commit = remote_apply). Las réplicas aplican los cambios con 1 s de retraso para que la diferencia se vea.

Síncrona — el primario espera a que la réplica confirme. Consistencia fuerte; cada escritura es más lenta y, sin réplica, se bloquea.
Asíncrona — el primario confirma y replica después. Más rápida y disponible; la réplica puede quedar desactualizada (consistencia eventual).

Teorema CAP

C · ConsistenciaTodos los nodos ven los mismos datos al mismo tiempo. → Modo síncrono; rechazar escrituras si no hay primario.
A · DisponibilidadEl sistema siempre responde, aunque el dato no sea el más reciente. → Failover de lectura a la réplica.
P · Tolerancia a particionesSigue funcionando con fallos de red entre nodos. → Inevitable en un sistema distribuido.
Lo que hace este sistema: lecturas → AP (si cae el primario, responde la réplica, posiblemente desactualizada). Escrituras → CP (si cae el primario, o en modo síncrono la réplica, se rechaza antes que arriesgar datos inconsistentes). Un banco elegiría CP también para lecturas; una red social, AP.
